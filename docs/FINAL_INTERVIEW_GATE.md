## 目标与职责
本关验收的是**研究者本人独立解释、推导、定位问题与证明贡献的能力**，不是 Codex 对自己生成的代码做自我评价。
- **研究者**：独立口头讲解、白板推导、打开源码定位、分析实验数据并回答追问；允许明确说不确定，不能让 Codex 代答。
- **Codex**：整理候选资料、源码入口、真实指标和题库；在面试前辅助复习，面试时不实时提示、不代答；面试后归档证据、弱项和建议。
- **面试官**：可由新的 ChatGPT 对话模拟或由真人担任；必须根据真实仓库版本和实验记录提出有区分度的题目，保存研究者原始回答。生成题库不等于完成验收。
- 五篇小论文完成且研究者批准之前，不准把本项目改造/迁移至冻结中的双 FR3 主工程。

## 开始条件（不满足不得宣称最终面试已通过）
- [ ] 选定本项目明确的**已验证复现范围**，区分官方 baseline、修改版、未完成任务。
- [ ] 有上游 commit、训练/评估代码版本、实验配置和可核实结果，指向 README、PROGRESS、EXPERIMENT_MATRIX、RESULTS/报告。
- [ ] 有亲自参与审查的实现/实验更改与至少一个失败分析或明确说明没有对应事件。
- [ ] 研究者已经通过各复现阶段的至少三道理解检查；这不自动代替最终综合验收。
- [ ] 整个项目**如仍 BLOCKED**，可以做“阶段模拟面试”，但标记 PRACTICE_ONLY，不算最终项目面试验收。

## 面试结构（建议 35–50 分钟，现场问答）
1. **3 分钟项目陈述（15 分）**：问题、方法、创新/上游差异、真正做了什么、目前能证明什么。
2. **10 分钟公式与控制/学习原理（20 分）**：白板解释训练损失、动力学或控制律、变量来源、关键假设；根据此项目实际算法出题。
3. **8–10 分钟源码追踪（20 分）**：随机挑真实路径，从 Observation/Action 或参考轨迹到控制和网络更新；不可只背文件名。
4. **8–10 分钟实验与统计（25 分）**：基线、变量控制、训练预算、评估指标、多个随机种子或明确的资源限制、结论可证明边界。
5. **6–12 分钟失败诊断与个人贡献（20 分）**：给一个真实或反事实异常；提出证据和可证伪方案，并说明自己与 Codex / 上游作者分别完成的内容。

**满分 100，合格线 80；五模块各至少拿到该模块满分的 60%。** 重大事实错误（编造实验或数据、把上游成果写成个人完成、把 Sim2Sim 称为真机 Sim2Real、完全无法定位关键算法代码）一票否决。以上为个人学习项目的建议性验收标准，非企业官方面试标准。

## 本项目题目池（面试官应变化措辞并随机追问，不得只按答案背诵）
1. **任务解释**：解释 ManiSkill 是仿真基准而非 PPO/SAC 算法；比较三个任务的接触、奖励与难点；说明选择首任务和基线的依据。
2. **强化学习数学**：不用提示推导或准确解释 PPO clipped objective、GAE，以及 SAC 双 Critic、Replay、Target、Entropy；对照本人实际使用算法，不存在的上游基线要指出。
3. **源码与控制接口**：按真实代码路径追踪 reset/step→observation→policy action→controller/physics→reward→update；说明动作缩放、频率、终止条件。
4. **实验与证据**：给出至少一个本人真实运行的基线、评估协议与置信区间/多随机种子（资源不足须说明）；解释为何 success rate 与 return 不等价。
5. **失败案例**：针对接触失败、动作饱和、奖励漏洞或环境偏移给出诊断假设、独立证据、一个可执行修复和对照实验。
