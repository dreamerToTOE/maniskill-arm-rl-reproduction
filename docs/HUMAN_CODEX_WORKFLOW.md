# 人与 Codex 分工规范 | Human × Codex Learning & Reproduction Contract

> 适用于本仓库的**全部复现阶段**。本文件既是 Codex 的执行规范，也是学习与面试验收规范；不代表已经开始或完成任何算法实验。
> 目标：不是让 AI 生成看起来完善的项目，而是让研究者能够独立理解、复述、推导、分析并面试答辩。

## 一、逐项责任分工（用户确认版）

| 工作 | 研究者（你） | Codex |
| --- | --- | --- |
| 理解论文研究问题与创新 | **主导** | 辅助解释 |
| 看懂 PPO/SAC 核心公式 | **必须掌握** | 讲解与验证 |
| 搭建仿真环境、安装依赖 | 审查 | **主导** |
| 阅读代码与梳理结构 | **必须参与** | 生成导读 |
| 实现和调试训练代码 | 理解关键模块 | **主导** |
| 设计奖励函数和对照实验 | **决定原则** | 实现与建议 |
| 跑实验、记录日志 | 审查 | **主导** |
| 分析为什么训练失败 | **亲自判断** | 提供数据和诊断 |
| 最终成果与面试准备 | **独立讲清楚** | 组织复习材料 |

各项目的方法未必都用 PPO/SAC：出现不同算法（如 AMP、动作跟踪或 Residual RL）时，应将“核心公式理解”推广至该项目**实际采用的算法**；不得为凑齐 PPO/SAC 假称上游存在对应基线。

## 二、执行流程：必须先理解，后扩展，再验证

1. **研究对象与实验范围**：Codex 完整阅读上游论文/仓库文档，给出“研究问题—方法—创新—公式—算法数据流—原文实验—可获取资源—复现缺口”导读；**研究者决定最终复现范围**。区别框架示例运行、官方基线重复、新实现基线、论文结果复现和个人扩展。
2. **算法学习关**：解释所采用算法的关键目标函数、更新变量、梯度路径、数据来源，所有关键公式与上游代码逐项映射。研究者应能用自己的话解释，不懂的知识点按需补课；**不要求事先学完所有 MPC/QP/WBC 等知识**。
3. **环境与代码关**：Codex 完成上游版本/License/数据审查、隔离环境、最小 Smoke Test、代码结构导读。研究者重点检查观察量、动作、奖励、重置、终止、频率和控制接口，并能指出关键实现文件。
4. **实验方案关**：研究者决定比较对象、变量、统计与公平性原则；Codex 提出建议、落实配置和验证，先提交有上限的训练/算力预算再执行。
5. **结果诊断关**：Codex 提供曲线、逐回合指标、失败轨迹、原始数据与诊断**假设**。研究者先做独立归因判断，再与 Codex 的证据和备选原因交叉核对。不得未经审查把 Codex 猜测写成结论。
6. **面试验收关**：研究者能够独立作 3 分钟介绍和 10–15 分钟技术追问，明确个人贡献、复现程度、失败记录和无法证明的结论；Codex 只辅助生成题库和反馈。

## 三、每个关卡的学习交付

Codex 在阶段报告中提供：
- **原理一页纸**：关键公式（变量/单位/梯度）、算法流程图的文字说明、涉及的上游源码位置。
- **代码导读**：入口、调用链、训练循环、经验采样、损失更新、保存和评估位置；指出需要自己读的 3–5 个关键文件/函数。
- **需要研究者回答的问题**：至少 3 个“为什么”问题（例如为何采用此动作语义、此奖励是否导致投机行为、此 Loss 更新了哪些网络）。
- **数据证据**：执行命令、依赖版本、Git SHA、GPU/环境步数、原始日志与结果路径；没有运行则写 `NOT_RUN`。
- **决策与下一步**：需要研究者批准的设计选择，需补的知识点，以及下一次**有边界**的执行建议。

只有研究者确认理解并批准实质性算法变更/高资源训练时，才进入对应阶段；允许低风险文档阅读、信息整理和只读环境检查先行。不要把用户的理解情况伪造为已通过。

## 四、研究边界与项目优先级

- **五篇小论文复现优先**。现有双 FR3 主工程（`dual-arm-embodied-palletizing`）暂停新功能、控制策略迁移和额外 RL/力控开发，直到该五篇复现工作完成且研究者明确允许恢复。
- 本仓库是**独立开源项目复现空间**，可以独立进行分析、隔离安装和已批准的实验；**不得修改 FR3 主仓库或其他研究仓库**，不得擅自向现有主工程集成结果。
- 缺少的 MPC、WBC、动力学等知识在实验遇到或准备相关岗位面试时再针对性补齐，不提前扩成无边界的课程计划。
- 严禁把运行官方 Demo、获取预训练权重或生成图片当作论文完整复现；严禁冒称真实硬件部署 / Sim2Real。
- 继续遵循根目录 `AGENTS.md` 的上游 SHA 固定、实验日志、三次失败止损、证据驱动、长任务需先批准等规则。
